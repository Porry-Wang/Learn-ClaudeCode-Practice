## 案例

现象：两套版本底层执行代码一致，共用同一个 SYSTEM 提示词、`run_bash` 工具、固定 `cwd=os.getcwd()`；成败差异完全来自模型输出的 shell 命令形态，不属于代码 bug，属于**提示词 + 工具使用范式缺陷**。

事故根因：项目目录名带空格 `Learn-ClaudeCode-Practice`。
v1 失败链路（5 轮交互，4 轮无效）
1. **模型主动幻觉缩写**：把 `Claude Code` 自行替换成 `[CC]`；它误以为方括号是环境里自带的别名，属于自行脑补的优化逻辑，环境上下文根本不存在这个别名。
2. 引号方案失效：`[CC]` 在 shell 里是 glob 字符集，目录原名不含方括号，加双引号也无法命中真实目录。模型在修复一个不存在的问题。
3. `cd X && cmd` 短路放大故障：cd 失败时，后续整条链路不会执行，无有效输出，模型缺少诊断信号，只能重试排查。
4. 诊断工具选型次优：`ls | head -50` 截断关键列表行；后续 `ls -b | od -c` 字节校验属于冗余诊断，第3轮已经拿到正确 pwd，第4轮纯浪费轮次。

v2 一次成功的核心：**命令中完全不携带路径**
```bash
printf 'print("Hello, World!")\n' > hello.py && cat hello.py && python3 hello.py
```
- 不需要模型复述、抄写易出错的路径字符串，**路径由工具层固定 cwd 兜底**，杜绝路径改写幻觉；
- 没有前置 cd 失败点，不存在短路导致整条命令不运行；
- **写文件、校验内容、执行放在一条链路，一次性拿到完整证据，单轮收敛**。

## 核心结论
Agent 模型本身不适合准确抄写、转述带特殊字符/空格的路径这类脆弱字符串。**尽量把路径绑定在工具执行层，而不是交给模型在命令里手写。**

| 维度 | v1（反例） | v2（正例） |
|---|---|---|
| 是否要求模型复述易错字符串 | ✅ 需要抄写带空格目录 | ❌ 不需要写任何路径 |
| 失败扩散 | cd 失败 → 整条命令不跑 | 无前置路径依赖 |
| 返回信息完整性 | 存在截断、信息缺失 | 全链路自校验，信息完整 |

## 改进建议
1. 系统提示词增加约束：工作目录已经固定为项目根目录，**禁止使用 cd 切换目录**（和 Claude Code 官方约束对齐）。
2. 工具返回强制带回当前工作目录：`return f"(cwd: {os.getcwd()})\n{output}"`，低成本消除模型对路径的猜测。
3. 工程规范：项目目录命名禁止空格、特殊符号，用短横线连接，从源头降低 shell 转义风险（比调 prompt 收益更高）。
4. 输出截断规范：如果工具返回做长度截断，必须显式追加标记 `...[truncated]`，避免模型误以为拿到了完整 ls 列表。
